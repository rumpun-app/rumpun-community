# Code and Contribution Provenance

Every contribution must have a lawful, reviewable origin.

## Contributor declaration

By submitting a contribution, the contributor confirms that:

- they authored it or have the right to submit it under AGPL-3.0-only
- it does not contain proprietary Rumpun material or other confidential information
- copied or adapted third-party material is identified with its source and license
- AI-assisted output has been reviewed and does not reproduce restricted material
- examples and fixtures contain synthetic data only

## Required disclosure

A pull request should disclose:

- source links for adapted specifications, standards, snippets, fixtures, or designs
- licenses and notices that must be preserved
- public ideas or prior implementations that materially influenced the approach
- whether the contributor had access to related non-public material and how contamination was avoided

## Clean-room rule

A contributor with access to non-public proprietary Rumpun code, designs, schemas, APIs, or roadmap material must not reproduce or paraphrase that material here. Work from public requirements and public specifications only. When doubt exists, stop and ask maintainers for a provenance review.

The same rule applies in reverse: Community code and protected materials may not enter proprietary Rumpun except through explicit AGPL-compliant use.

## Maintainer review

Maintainers may request authorship history, source links, license clarification, or independent reimplementation. Ambiguous contributions may be closed without judging intent. Provenance clarity beats merge speed.

## Records

Relevant source links and license notes should remain in the pull request, commit, source header, or a dedicated `NOTICE` file so future maintainers can reconstruct origin.
