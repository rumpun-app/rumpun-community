# Security Policy

## Supported versions

The project has not released a stable version yet. This policy covers the default branch and future supported releases listed here.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub private vulnerability reporting when enabled, or contact the maintainers through the organization's private security channel.

Include impact, affected component or commit, reproduction steps, proof of concept where safe, and suggested mitigation. Do not include real family data.

Maintainers aim to acknowledge reports within 7 days. Timelines for validation and remediation depend on severity and project capacity.

## Scope

Security reports may cover authentication, authorization, data exposure, import parsing, uploads, dependency risk, backup/restore, and deployment defaults. Rumpun Community does not claim zero-knowledge or end-to-end encryption.
